## 1) รูปแบบภาพ (สี / Grayscale / Binary / ขั้ว / JPEG)

`TestingCNN.py` อ่านภาพด้วย `imread(as_gray=True)` แปลงทุกแบบเป็น Grayscale 1 ช่องก่อนเข้าโมเดล

| รูปแบบภาพ | วิธีสร้าง | Round 2 | `img96_nomp` |
|---|---|---|---|
| Grayscale (ต้นฉบับ) | — | 297/342 = 86.8% | 306/342 = 89.5% |
| RGB 3 ช่อง | แปลงเป็น RGB (ค่าเท่ากันทุกช่อง) | 297/342 = 86.8% | 306/342 = 89.5% |
| RGBA (มี alpha) | RGBA, alpha = 255 | 297/342 = 86.8% | 306/342 = 89.5% |
| JPEG คุณภาพ 30 | บันทึกเป็น JPEG quality=30 | 297/342 = 86.8% | 306/342 = 89.5% |
| Binary 0/255 | threshold 128 → 0/255 (uint8) | 300/342 = 87.7% | 306/342 = 89.5% |
| Binary แบบ mode '1' | threshold 128 → PIL mode '1' | 288/342 = 84.2% | 303/342 = 88.6% |
| สีน้ำเงินเข้มบนเหลืองอ่อน | ตัวอักษร (0,0,160) บนพื้น (255,255,150) | 299/342 = 87.4% | 307/342 = 89.8% |
| **สีแดงบนเขียว (คอนทราสต์ต่ำ)** | ตัวอักษร (200,0,0) บนพื้น (0,160,0) — ความสว่างใกล้กันมาก | **72/342 = 21.1%** | **89/342 = 26.0%** |
| **กลับสี (ขาวบนดำ)** | 255 − ค่าพิกเซล | **57/342 = 16.7%** | **57/342 = 16.7%** |

**สรุป**
- **ไม่มีผล (ต่างไม่เกิน ~1 จุด):** สีที่คอนทราสต์ปกติ, RGB/RGBA, JPEG, Binary แบบ 0/255 (Round 2 ดีขึ้น +0.9 จุด)
- **ลดเล็กน้อย:** Binary แบบ mode '1' (Round 2 −2.6 จุด, `img96_nomp` −0.9 จุด) — ยังไม่ได้ตรวจสาเหตุ
- **พังหนัก:** ภาพกลับสี (โมเดลเรียนแบบตัวอักษรดำบนพื้นขาวเท่านั้น และโค้ดไม่มีการตรวจ/กลับขั้ว) และภาพสีที่ความสว่างตัวอักษรกับพื้นใกล้กัน (แปลง Grayscale แล้วเกือบกลืนกัน)
- คู่สีแดง/เขียวที่เลือกเป็นกรณีสุดโต่ง ภาพจริงส่วนใหญ่คงคอนทราสต์ดีกว่านี้

## 2) การทำให้แหว่ง (ตัวอักษรไม่สมบูรณ์)

| การทำให้แหว่ง | วิธีสร้าง | Round 2 | `img96_nomp` |
|---|---|---|---|
| ไม่ทำลาย (ต้นฉบับ) | — | 297/342 = 86.8% | 306/342 = 89.5% |
| ลบพิกเซลหมึกสุ่ม 10% | เปลี่ยนพิกเซลดำ 10% เป็นขาว | 294/342 = 86.0% | 298/342 = 87.1% |
| ลบพิกเซลหมึกสุ่ม 20% | 20% | 275/342 = 80.4% | 289/342 = 84.5% |
| ลบพิกเซลหมึกสุ่ม 30% | 30% | 229/342 = 67.0% | 259/342 = 75.7% |
| ลบสี่เหลี่ยมสุ่ม 15% | ก้อนขาว 2 ก้อน กว้าง/สูง 15% ของภาพ (ตำแหน่งสุ่ม) | 289/342 = 84.5% | 295/342 = 86.3% |
| ลบสี่เหลี่ยมสุ่ม 30% | ก้อนขาว 2 ก้อน กว้าง/สูง 30% | 218/342 = 63.7% | 229/342 = 67.0% |
| ลบขอบขวา 15% | ทาขาว 15% ของความกว้างด้านขวา | 290/342 = 84.8% | 302/342 = 88.3% |
| ลบขอบขวา 30% | 30% | 206/342 = 60.2% | 180/342 = 52.6% |
| ลบขอบบน 15% | ทาขาว 15% ของความสูงด้านบน | 267/342 = 78.1% | 293/342 = 85.7% |
| **เส้นบางลง 1 พิกเซล** | `MaxFilter(3)` (ทำให้หมึกบางลง) | **142/342 = 41.5%** | **193/342 = 56.4%** |
| รอยขาดแนวนอน 1 เส้น | ทาขาว 1 แถวพิกเซลที่ความสูง 1/3–2/3 ของภาพ | 297/342 = 86.8% | 296/342 = 86.5% |

**สรุป**
- **แหว่งเล็กน้อย (≤10–15%):** ลดลง 1–3 จุด ยังใช้ได้
- **แหว่งปานกลางถึงมาก (20–30%):** ลดเหลือประมาณ 60–75%; ตัดขอบขวา 30% เหลือ 53–60%
- **เส้นบางลงเป็นแบบที่แย่สุด (42–56%):** เส้นตัวอักษรใน synthetic หนาแค่ 2–4 พิกเซล การบางลง 1 พิกเซลทำให้เส้นบางส่วนขาดไปเลย
- **สองโมเดลไม่ได้ดีกว่ากันทุกกรณี:** `img96_nomp` ทนพิกเซลหายและเส้นบางได้ดีกว่า Round 2 ชัด แต่ตัดขอบขวา 30% แย่กว่า
- ขั้นตอนเติมข้อมูลของเรา (หมุน ±15° + noise) ไม่มีการลบส่วนของภาพหรือปรับความหนาเส้น โมเดลจึงไม่เคยถูกฝึกกับภาพแหว่งโดยตรง (ข้อสันนิษฐาน: ชุดของอาจารย์เองน่าจะหยาบอยู่บ้างจึงทนได้ระดับหนึ่ง)

## ข้อจำกัดของผลทดสอบ

- ทดสอบกับภาพ synthetic ที่ดัดแปลง **ไม่ใช่ภาพถ่าย/ลายมือ/สแกนจริง** ผลกับภาพจริงยังไม่ทราบ
- การทำลายแบบสุ่มใช้ seed เดียว ชุดภาพ 342 ภาพ — ความต่างประมาณ 2–3 จุดอยู่ในช่วง noise (1 ภาพ ≈ 0.3 จุด)
- โมเดล `img96_nomp` เป็นรอบเดียวที่ไม่ได้ตั้ง seed (ตัวอื่นที่ทำซ้ำ `s1`, `s2` ไม่ได้ทดสอบ) จึงยังไม่ทราบว่าผลด้านนี้แกว่งระหว่างรอบแค่ไหน
- ไม่ได้ทดสอบภาพจริงที่ชุดทดสอบของอาจารย์ (ยังไม่มีชุดนั้น)
