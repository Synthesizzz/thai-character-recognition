## 1) รูปแบบภาพ (สี / Grayscale / Binary / ขั้ว / JPEG)

`TestingCNN.py` อ่านภาพด้วย `imread(as_gray=True)` แปลงทุกแบบเป็น Grayscale 1 ช่องก่อนเข้าโมเดล

| รูปแบบภาพ | วิธีสร้าง | Round 2 | `img96_nomp` |
|---|---|---|---|
| Grayscale (ต้นฉบับ) | — | 297/342 = 86.8% | 306/342 = 89.5% |
| RGB 3 ช่อง | แปลงเป็น RGB (ค่าเท่ากันทุกช่อง) | 297/342 = 86.8% | 306/342 = 89.5% |
| RGBA (มี alpha) | RGBA, alpha = 255 | 297/342 = 86.8% | 306/342 = 89.5% |
| JPEG คุณภาพ 30 | บันทึกเป็น JPEG quality=30 | 297/342 = 86.8% | 306/342 = 89.5% |
| Binary 0/255 | threshold 128 → 0/255 (uint8) | 300/342 = 87.7% | 306/342 = 89.5% |
| Binary แบบ mode '1' | threshold 128 → PIL mode '1' | 288/342 = 84.2% | 303/342 = 88.6% |
| สีน้ำเงินเข้มบนเหลืองอ่อน | ตัวอักษร (0,0,160) บนพื้น (255,255,150) | 299/342 = 87.4% | 307/342 = 89.8% |
| **สีแดงบนเขียว (คอนทราสต์ต่ำ)** | ตัวอักษร (200,0,0) บนพื้น (0,160,0) — ความสว่างใกล้กันมาก | **72/342 = 21.1%** | **89/342 = 26.0%** |
| **กลับสี (ขาวบนดำ)** | 255 − ค่าพิกเซล | **57/342 = 16.7%** | **57/342 = 16.7%** |

**สรุป**
- **ไม่มีผล (ต่างไม่เกิน ~1 จุด):** สีที่คอนทราสต์ปกติ, RGB/RGBA, JPEG, Binary แบบ 0/255 (Round 2 ดีขึ้น +0.9 จุด)
- **ลดเล็กน้อย:** Binary แบบ mode '1' (Round 2 −2.6 จุด, `img96_nomp` −0.9 จุด) — ตรวจสาเหตุแล้ว: ดูหัวข้อ 3.1 (ภาพ 1-bit ถูก resize แบบ nearest)
- **พังหนัก:** ภาพกลับสี (โมเดลเรียนแบบตัวอักษรดำบนพื้นขาวเท่านั้น และโค้ดไม่มีการตรวจ/กลับขั้ว) และภาพสีที่ความสว่างตัวอักษรกับพื้นใกล้กัน (แปลง Grayscale แล้วเกือบกลืนกัน)
- คู่สีแดง/เขียวที่เลือกเป็นกรณีสุดโต่ง ภาพจริงส่วนใหญ่คงคอนทราสต์ดีกว่านี้

**สรุป**
- **แหว่งเล็กน้อย (≤10–15%):** ลดลง 1–3 จุด ยังใช้ได้
- **แหว่งปานกลางถึงมาก (20–30%):** ลดเหลือประมาณ 60–75%; ตัดขอบขวา 30% เหลือ 53–60%
- **เส้นบางลงเป็นแบบที่แย่สุด (42–56%):** เส้นตัวอักษรใน synthetic หนาแค่ 2–4 พิกเซล การบางลง 1 พิกเซลทำให้เส้นบางส่วนขาดไปเลย
- **สองโมเดลไม่ได้ดีกว่ากันทุกกรณี:** `img96_nomp` ทนพิกเซลหายและเส้นบางได้ดีกว่า Round 2 ชัด แต่ตัดขอบขวา 30% แย่กว่า
- ขั้นตอนเติมข้อมูลของเรา (หมุน ±15° + noise) ไม่มีการลบส่วนของภาพหรือปรับความหนาเส้น โมเดลจึงไม่เคยถูกฝึกกับภาพแหว่งโดยตรง (ข้อสันนิษฐาน: ชุดของอาจารย์เองน่าจะหยาบอยู่บ้างจึงทนได้ระดับหนึ่ง)

## 3) Round 5 (augmentation ใหม่) เทียบกับ Round 2 และ `img96_nomp`

โมเดล Round 5 = `Round 5/runs/img96_nomp_aug_s1` (เทรนบน Google Colab, seed 1, 55 epoch, best val_acc 98.53%) ทดสอบด้วยชุดภาพและวิธีเดียวกับหัวข้อ 1 และ 2
การทำลายภาพแบบสุ่มของทุกโมเดลใช้ seed เดียวกัน จึงเป็นภาพแหว่งชุดเดียวกัน

### 3.1) รูปแบบภาพ

| รูปแบบภาพ | Round 2 | `img96_nomp` | **Round 5** |
|---|---|---|---|
| Grayscale (ต้นฉบับ) | 86.8% | 89.5% | 302/342 = 88.3% |
| RGB 3 ช่อง | 86.8% | 89.5% | 302/342 = 88.3% |
| RGBA (มี alpha) | 86.8% | 89.5% | 302/342 = 88.3% |
| JPEG คุณภาพ 30 | 86.8% | 89.5% | 300/342 = 87.7% |
| Binary 0/255 (uint8) | 87.7% | 89.5% | 314/342 = **91.8%** |
| Binary แบบ mode '1' (1-bit) | 84.2% * | 88.6% * | 314/342 = **91.8%** (ก่อนแก้ `TestingCNN.py`: 258/342 = **75.4%**) |
| สีน้ำเงินเข้มบนเหลืองอ่อน | 87.4% | 89.8% | 302/342 = 88.3% |
| สีแดงบนเขียว (คอนทราสต์ต่ำ) | 21.1% | 26.0% | 89/342 = 26.0% |
| กลับสี (ขาวบนดำ) | 16.7% | 16.7% | 53/342 = 15.5% |

**การค้นพบเรื่องภาพ 1-bit (mode '1'):** ภาพ binary ชุดเดียวกัน (พิกเซลเหมือนกันทุกจุด) แต่บันทึกต่างกัน ให้ผลต่างกัน 16 จุด (91.8% เทียบ 75.4%)
เพราะ `imread` คืน dtype `bool` สำหรับภาพ 1-bit แล้ว `skimage.transform.resize` ใช้ nearest-neighbor กับภาพ bool (ขอบเป็นบล็อก ต่างจากภาพ 8-bit ที่ resize แบบ bilinear
ตอนเทรน) แก้โดยแปลง bool เป็น uint8 × 255 ก่อน resize ใน `Round 5/TestingCNN.py` (1 บรรทัด) — หลังแก้ได้ 91.8% เท่ากับแบบ uint8 พอดี และผลบน synthetic ปกติ (PNG 8-bit) ไม่เปลี่ยน (302/432 เท่าเดิม)
\* ตัวเลขของ Round 2 และ `img96_nomp` วัดด้วยโค้ด `TestingCNN.py` ก่อนแก้ จึงยังมีความไวต่อภาพ 1-bit นี้ (ไม่ได้แก้โฟลเดอร์ Round 2 ตามที่ตกลง)
ถ้าชุดทดสอบวันสอบเป็นภาพ 8-bit ปกติ (JPEG/PNG) ไม่กระทบ

**สรุปหัวข้อ 3**
- augmentation ใหม่ช่วยเรื่องภาพแหว่ง/เส้นบางได้มาก (ลบพิกเซล 30% +12 จุด, ลบก้อน 30% +15 จุด, ลบขอบขวา 30% +16 จุด, เส้นบาง +26 จุด) โดยภาพปกติไม่เสีย
  (88.3% เทียบ 89.5%, ต่าง 4 ภาพ อยู่ในช่วงแกว่งปกติ; val_acc 98.53% เทียบ `img96_nomp` เฉลี่ย 98.49%; synthetic 302/432 อยู่ในช่วง 298–307 ของสามรอบเดิม)
- ไม่ช่วยเรื่องภาพกลับสีและสีคอนทราสต์ต่ำ (ไม่ได้ออกแบบมาแก้)
- ลบพิกเซล 10–20% ให้ผลสูงกว่าภาพต้นฉบับ (89.5–90.1% เทียบ 88.3%) และ Binary 0/255 สูงขึ้น (91.8%) — ข้อสันนิษฐาน (ยังไม่ได้ทดสอบ): โมเดลนี้ชอบภาพที่หมึกบางกว่าเล็กน้อย

**ข้อควรระวังของหัวข้อ 3:** Round 5 เทรนรอบเดียว (Colab GPU) เทียบกับ `img96_nomp` ที่เทรนบนเครื่องเรา (DirectML) ไม่ได้ตั้ง seed เหมือนกัน; และการทดสอบ "แหว่ง" ใกล้เคียงกับสิ่งที่ augmentation ฝึกไว้ (ลบส่วนของภาพ, ปรับความหนาเส้น)
ผลจึงอาจประเมินความทนต่อความเสียหายจริงสูงเกินไป (ลายมือขาดหรือสแกนเลอะจริงอาจต่างจากที่จำลอง) ควรเทรนซ้ำด้วย seed อื่นก่อนสรุปจริงจัง

## ข้อจำกัดของผลทดสอบ

- ทดสอบกับภาพ synthetic ที่ดัดแปลง **ไม่ใช่ภาพถ่าย/ลายมือ/สแกนจริง** ผลกับภาพจริงยังไม่ทราบ
- การทำลายแบบสุ่มใช้ seed เดียว ชุดภาพ 342 ภาพ — ความต่างประมาณ 2–3 จุดอยู่ในช่วง noise (1 ภาพ ≈ 0.3 จุด)
- โมเดล `img96_nomp` เป็นรอบเดียวที่ไม่ได้ตั้ง seed (ตัวอื่นที่ทำซ้ำ `s1`, `s2` ไม่ได้ทดสอบ) จึงยังไม่ทราบว่าผลด้านนี้แกว่งระหว่างรอบแค่ไหน
- ไม่ได้ทดสอบภาพจริงที่ชุดทดสอบของอาจารย์ (ยังไม่มีชุดนั้น)
